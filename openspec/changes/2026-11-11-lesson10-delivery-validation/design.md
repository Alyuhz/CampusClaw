# Design

## Context

项目使用 Python3.12/Flask/SQLite FTS5、JWT+服务端会话、一次性CSRF、七列审计。现有 make check 收集 tests 与 apitest/cases，第九课最终证据为51通过；本次规划未重跑。make check-security 已含秘密历史/两份锁审计，CI当前只跑门禁、不构建镜像。Compose只有 app+持久卷；Docker已多阶段，但 COPY业务.py，现有 /health 只验证SELECT1。没有指标、面板、压测、root report.md；skills/ 为工程技能，非课堂四个业务技能。

第九课尚有真实模型、独立组员和课程适配的外部待办。本次基于其实际未提交文件，不把其22/25当成全部验收完成。主规约清单为空，历史归档与活动规约都纳入追溯，不改历史归档。

## Goals / Non-Goals

**Goals:** 交付能在干净目录复跑、能观察真实运行、能比较性能改进且证据与代码对应的现有项目。

**Non-Goals:** 不迁移MySQL、不引入Qdrant、不新增教学技能或异步作业。不以本地成功代替真实远端构建、外部通知、三人使用或手机实机证据。所有原版差异在 report.md 保持可见。

## Decisions

### 1. 关键取舍：复用双门禁，保留已有安全覆盖

新建 commands.md 记录每条命令最近实测时间/版本/退出码。traceability.md 从历史场景、第九课活动场景和本课Scenario映射到pytest nodeid，不只匹配文件存在。当前适用用例未覆盖数必须0；解题引导/教师改分/错题讲解/异步明确不存在，跨班知识库为空是实际用例。

make check 继续保留现有安全回归，make check-security 独立审计并额外执行明确的安全用例选择（pytest标记或固定目录）。两命令可以共享用例，但任何一侧都不删原断言来人为分离。CI使用两条同名命令，失败后不执行构建。

第十课红绿在临时隔离项目副本改坏已知断言，用同一make check得到准确失败，再恢复同内容得到0。临时副本包含当前未跟踪实现，不用git archive漏掉工作区；排除.env/instance/.git/缓存，依赖环境使用已锁定环境。归档改坏diff、两次完整输出、源码摘要和恢复检查，不动主工作区用例。

### 2. 运行打包与就绪

保留SQLite卷，默认Compose只跑app；不摆设两个未使用数据库来凑服务数。新增telemetry profile运行Prometheus/Grafana/Alertmanager与本地通知接收器，不成为默认业务启动的硬依赖。

构建阶段先产出应用wheel/包、编译相邻.pyc（与目标Python3.12一致），再仅交付业务.pyc和模板/静态/提示词/迁移SQL。运行镜像不复制业务.py、tests、开发工具或构建目录；运行依赖和标准库可能包含其自身.py，这个范围明确记录。源码不可见不作为保密或防逆向承诺。补启动、页面资源、提示词定位、迁移及模型替身回归，防止__file__路径变化损坏资源加载。

README完整列出前置软件、.env必填项及镜像版本准备，再在干净临时目录用独立项目名/卷执行docker compose up -d，180秒超时。Compose healthcheck指向/ready，无脚本等待循环。SQLite是内嵌数据库，无外部db服务可depends_on；观测服务则使用真实健康依赖。

/health保留已有合同；新增公开只读/ready，检查必要表、迁移版本与业务读取能力，故障为503。探针不调用外部模型、不写业务数据。生产接流量必须以ready为准，不能把Compose healthcheck本身宣传成完整负载均衡器。

### 3. 来源可查的构建流水线

CI顺序为检出→安装原锁文件与浏览器→make check→make check-security→构建镜像，使用github.sha作完整提交标签/OCI revision，构建产物保存摘要和运行号。版本配置不进镜像，构建来源元数据不含秘密。远端实际触发后记录run ID/提交SHA/镜像摘要；仅配置文件存在不能判流水线通过。

本地未提交构建标明基线+工作区SHA256清单，生成build-info与worktree标识，不能只贴HEAD。干净提交镜像和工作区镜像的验收路径分开。主干保护和真实推送构建作为外部验收任务，不自动把本地测试转写成远端成功。

### 4. 持久观测、多worker与指标保护

采用固定capability=materials-upload/knowledge-search/grounded-ask与status维度；业务技能不存在，指标命名capability_requests_total和capability_duration_seconds，不伪造skill_invocations_total。指标不带user/class/question/原始URL等高基数或敏感标签。

计数/直方图复用七列审计的操作与结果口径，以服务端event_id去重。新增持久聚合表，正常存储条件下完成事件与聚合更新保持事务一致，已聚合标记保证多worker/重试只计一次；耗时在最终响应阶段写入。旧审计不默认当作本次HTTP指标，以启用时间为起点。数据库不可用时明确抓取失败，不返回全0冒充健康；Prometheus同时监控up。

耗时桶固定5/10/25/50/100/250/500/1000/2500/5000ms与+Inf。当前执行中请求由独立请求lease记录，各worker开始/结束更新、5秒续约、30秒过期；异常退出最多30秒清除，不冒充异步队列。记录此机制对SQLite写压力的成本并纳入压测。

/internal/metrics使用独立环境令牌、恒时比较，只供内部观测网络抓取，不接受业务学生令牌代替；配置不写前端或镜像。指标基础聚合正常重启不清零。Prometheus按15秒抓取、规则15秒评估。Grafana预置三组面板：三能力调用量/每能力错误率/路由P95与执行中请求。错误率按status>=400计数除总数，含403，面板计算不单独上报率。

告警规则：最近2分钟至少20个请求且错误率>1%，持续2分钟→Alertmanager→本地HTTP测试接收器。实验每秒产生一次合法学生身份的越权上传403，持续4分钟或至送达；满足for后60秒内、整个实验5分钟内有接收证据。记录规则、目标、firing/receiver时间、面板URL与恢复事件。真实负责人渠道是单独外部事项，本地接收记录不冒充已通知负责人。

### 5. 同条件压测与班级安全缓存

使用Python标准库HTTP客户端+线程并发，参数全走环境/CLI，保留JSON原始样本。只用临时部署与合成资料；上传POST /materials量的是同步完整创建201，不假称异步接收能力；查询GET /materials/{id}、检索GET /search分别统计。每个worker有独立Cookie与身份，每次写请求前独立取CSRF，令牌获取成本单列并同时报告端到端成本。

固定两班各200份资料、每份20片段；并发1/4/8/16/32，预热5秒、测量20秒，重复3次。workers固定2、每worker4线程并启用HTTP长连接，模型采用确定性抽取式路径，禁用真实模型费用。每轮从相同SQLite备份恢复、使用同一数据生成种子、机器和观测配置；上传产生的数据不带到下轮。报告脚本SHA、配置SHA、数据SHA、Python/镜像/源码摘要与样本量。

饱和判据：某档错误率>1%或P95>500ms，或相邻两档并发增加而吞吐提升<10%；标出实际观测点。若到32并发仍无判据命中，报告该范围未观测到，不外推。区分客户端CPU/连接开销与服务端SQLite锁/FTS成本，不能仅凭曲线断言数据库瓶颈。

选用有界检索缓存：每进程LRU最多256项、TTL30秒，键含服务端class_id、数据库class_revision、规范化q、limit；缓存结果不可由调用者原地修改。新增class_revisions表，上传成功在同一业务事务递增版本，回滚不递增；检索每次读取当前版本，确保别的worker写入后下次请求失效。鉴权在缓存前，登出/撤销不可绕过。新实例初始版本0处理现有资料；新数据变更入口未来也须递增。

基线用相同实现SEARCH_CACHE_ENABLED=false，改进仅切true，其他参数与数据不变；另记录真正改进代码的工作区diff/来源。冷热结果分别标识。重复测量至少2/3同方向、检索吞吐或P95改善>=10%且错误率不增加才称有效；没达到必须继续定位/调整并重测，不能填预设数字。

### 6. H5、反馈和交付证据

现有页面与API默认同源，手机访问同一HTTP服务即可；不额外开放宽泛CORS。如未来不同源客户端，需单独列精确origin和Cookie/凭据合同。本课先验证移动视口自动化，再由真实手机走同步四步，审计保留完整身份与结果。

reports/feedback.md必须有3名真实使用者各至少一条记录，匿名会话标识、实际接口/返回、预期与实际差异、处理任务或不做理由；没有人就保持未执行。反馈中新缺陷先补复现用例。

七类核查在既有AGENTS/.cursor规则中按最小补充落地，不降低安全约束；按入口/逻辑/数据库/公共函数/错误/安全/性能逐类注明AI、脚本或人工。风险三查分别写并发缓存/指标与SQLite竞争、事务原子与迁移、指标与缓存授权。review-05/06/07用于本课，不覆盖第九课review-02/03/04；至少两份来自脚本或AI，第三份人工需实际完成。

根report.md仅写结论、证据链接和待办。reports/gate-red-green.md保留第九课章节并追加第十课链接；原始输出放reports/lesson10/。其余必需根路径bench.md、feedback.md、risk-concurrency.md、risk-transaction.md、risk-authz.md与命令/追溯/观测记录都索引到原始版本证据。

## Risks / Trade-offs

- 字节码打包影响资源路径/调试 → 固定Python版本、资源烟测、源码摘要对应；依赖源码范围不误报。
- SQLite同时承载业务/审计/指标产生写竞争 → 精确事务去重、短更新、按相同观测负载压测，不能牺牲审计一致性换速度。
- 缓存跨班或写后旧数据 → 班级+持久版本键、双worker失效/回滚/吊销回归。
- 压测或红绿污染现有数据 → 独立临时目录/卷/合成数据，清理脚本只清自己创建的资源。
- 第九课证据被覆盖 → 第十课原始证据独立目录，根报告分章节索引。
- 本地接收/模拟手机被误认真实外部验收 → 标签写清，真实负责人/实机/三人/远端单独待办。

## Migration Plan

先备份和盘点真实工作区，新增不可变迁移扩展class_revisions与指标聚合/lease；历史业务数据不删改。完成迁移再启用缓存与观测（扩→迁），本课不缩旧结构。每步测试失败停止下一步。

应用/前端/观测配置共同发布；回滚关闭缓存与观测、恢复兼容应用，保留新增表与审计证据。验证旧数据、备份恢复、并行迁移和就绪故障。干净目录启动与告警/压测在隔离环境执行；外部验收完成前不归档成全通过。

### 实施时的压测传输修正

首次短连接试跑在macOS耗尽临时端口，属于客户端故障，原数据保留但不用于收益结论。正式脚本使用每客户端独立HTTP长连接，Gunicorn双worker各4线程支持keep-alive，前后两轮固定此配置。GET断链可重连一次，POST不自动重放，避免重复上传；预热计时从所有客户端就绪时开始。
