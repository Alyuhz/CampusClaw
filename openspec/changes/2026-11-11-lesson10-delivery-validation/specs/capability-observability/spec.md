# Spec Delta

## Purpose

为现有资料上传、知识检索和问答提供真实且可核对的运行观测，保证多进程和重启不丢计数。通过实际触发和接收的告警验证观测链路，而不把不存在的技能或任务队列画成成功指标。

## ADDED Requirements

### Requirement: 准确且受保护的指标
系统 SHALL 按固定 capability 与 status 维度记录调用次数与耗时分布；多worker与重启 MUST 不漏计、重复计或混入敏感标签；抓取接口 MUST 有独立保护。

#### Scenario: 多进程精确计数
- **前置条件**：正常存储条件、两个worker、已知基线和三个能力各固定10次请求
- **WHEN / 操作**：并发请求、抓取指标，再重启并抓取
- **THEN / 可观测结果**：各能力增量与已完成请求逐项一致、重启不清零；没有身份/班级/问题/令牌标签；无抓取凭据为401或403。

### Requirement: 三组真实面板
面板 SHALL 展示三能力调用量分线、每能力错误率、接口P95与当前执行中请求数；错误率 MUST 由计数算出，不单独伪造上报。

#### Scenario: 生成真实流量
- **前置条件**：观测profile启动并抓取真实请求
- **WHEN / 操作**：为三个能力分别制造正常和失败样本
- **THEN / 可观测结果**：三组图都有可查询非空数据，错误率与原始计数相符；无队列能力处标不适用，不用执行中请求冒充队列深度。

### Requirement: 真实告警触发与送达
告警 SHALL 有观察量、窗口、持续条件和动作；连续错误 MUST 实际送达本地测试接收器并保留触发/接收时间与面板链接。

#### Scenario: 持续错误触发
- **前置条件**：三能力观测和本地接收器正常
- **WHEN / 操作**：对上传入口持续产生403，使2分钟错误率>1%且样本>=20，并持续2分钟
- **THEN / 可观测结果**：满足持续条件后60秒内接收器收到实际告警，5分钟内有送达记录；恢复后有恢复状态。本地接收不冒充负责人外部通知。
