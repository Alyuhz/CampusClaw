# Proposal

## Why

### 为什么
第九课要求以真实安全复测变绿作为修复依据。仅整理文档不足以完成课程范围，需要补齐当前项目的认证默认拒绝、写入服务授权、注入回归、安全门禁和持久审计。

## What Changes

### 本次做到哪
- 固定 SEC-01～08 首次基线，先复现再修复；现有绿项保留回归。
- SEC-01：默认保护 API；SEC-02：保留 FTS/LIKE 班级过滤与单行详情归属校验；SEC-03/04：接口及事务内写入验证服务端身份、角色与班级。
- SQL、实际 DOM XSS、跨站 CSRF 三件套接入 make check。**BREAKING**：状态变更需会话绑定 Cookie 与一次性 CSRF 令牌，旧客户端需更新。
- SEC-05/06：历史密钥扫描、依赖升级和 make check-security 门禁，实际红绿证据归档；有泄露时先轮换，再协调清历史。
- SEC-07：七列审计持久化，教师仅查本班，拒绝也落库；写业务与成功日志同事务。
- SEC-08：四步可重复恶意模型替身实验，记录被带偏现象与执行层拒绝；真实模型条件不足明确待执行。
- 完成回归、镜像检查、双人复核记录与本地工作区版本证据。

### 本次不做
不从其他项目移植第八课，不补建当前不存在的异步任务、评分、技能配置、向量库或模型密钥数据库字段。相关原版验收条目保留不适用说明与课程适配待确认，不能用同步问答冒充异步验收。

### 与既有约定
SQL 仅 db.py、身份取服务端用户记录、统一响应、模型测试使用替身。修改 OpenSpec/Makefile/scripts/CI 是为落实课堂安全检查与证据，影响为增加严格检查；验证为完整回归、安全门禁真实红绿与严格规约校验，不放宽门禁。

## Capabilities

### New Capabilities
- `security-access-boundaries`：默认认证、角色与底层写入归属边界。
- `security-injection-regression`：SQL/XSS/CSRF 可执行回归与客户端适配。
- `security-asset-gates`：密钥历史、依赖审计与失败阻断。
- `security-audit-evidence`：七列持久审计、四步实验和交付证据。

### Modified Capabilities
无现有主规约变更，历史归档保留。

## Impact
所有改动保持本地未提交、未推送。修改认证、持久层、HTTP 审计、前端 CSRF 配套、迁移、依赖锁文件、测试和门禁。文档阶段的 11 项完成仅代表文档框架，不能当成本轮实现完成。外部轮换、另一成员复核、真实模型条件和课程适配需真实证据。
