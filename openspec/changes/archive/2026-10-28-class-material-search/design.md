# 设计：class-material-search

## 选型

- Web 框架使用 Flask 3.1，保持课程允许的 Python 技术栈并支持应用工厂测试。
- 业务库与全文索引都使用 SQLite；FTS5 采用 trigram 分词，短查询或分词不命中时回退到
  参数化 `LIKE` 查询。
- 身份使用 HS256 JWT 作为传输凭证，服务端保存会话 `jti`，退出时立即吊销。
- 文件在服务端重命名后只把正文与元数据写入数据库；当前规模无需独立对象存储。
- 回答生成通过 `GlmClient` 路径隔离；无 Key 时返回带真实引用的抽取式结果。

## 分层

`campusclaw/app.py` 负责配置、初始化和路由装配；`auth`、`materials`、`search`、
`assistant` 承载业务能力；所有 SQL 集中在 `campusclaw/db.py`。依赖方向固定为
路由 → 业务 → 数据访问，不允许业务反向导入 Flask 应用配置或直接访问 SQLite。

## 关键取舍

1. **SQLite 而非独立 MySQL/Qdrant。** 当前数据量和部署目标以课程小组单机为主；代价是
   并发与多实例扩展能力有限。数据访问集中在 `db.py`，后续可在不变更接口语义的前提下替换。
2. **FTS5 trigram 加 LIKE 回退。** trigram 可处理中文子串并保持本地可运行；代价是短查询
   仍走 `LIKE`。相比只做全表扫描，常用中文查询获得了索引能力，同时保留可预测的降级。
3. **确定性抽取式答案作为无 Key 回退。** 课程环境不应依赖付费服务才能验收；代价是回答
   不具生成能力。回退必须在响应中标记 `degraded=true`，不能伪装成模型回答。
4. **响应体不包含 request_id。** 标识放在 `X-Request-ID` 响应头，使“跨班资源”和
   “不存在资源”可以做到响应体逐字节一致，同时保留请求关联能力。
