# 变更：class-material-search

## 为什么

学生目前只能依靠教师重复答疑，课程资料没有统一的检索入口。首个可运行版本需要先证明
“资料入库 → 本班检索 → 带真实出处回答”这条链路能够工作，并把权限、配置、日志和
验收方式固定在骨架中，供后续能力增量叠加。

## 本次做到哪

- 提供教师与学生登录，身份和所属班级只取自服务端用户记录。
- 教师上传 UTF-8 的 Markdown/TXT 资料，系统按段切片并建立 SQLite FTS5 索引。
- 学生与教师只能检索、读取和提问本班资料。
- 回答最多引用五条真实命中；没有命中时固定返回“资料中未找到相关内容”。
- 未配置 GLM Key 时使用确定性抽取式回答并标记降级；配置 Key 后走版本化提示词。
- 提供免认证 `/health`、单行 JSON 日志、`make check` 门禁与容器化启动入口。

## 本次不做

- 不解析 PDF、Word 或扫描图片。
- 不实现向量检索、混合检索或跨资料综合问答。
- 不提供资料修改、删除、版本恢复与教师统计后台。
- 不实现学生会话历史持久化。
- 不在本地测试中调用真实 GLM 服务。

## 与既有约定的关系

本次将 README 中的首期目标落为可运行基线。后续能力沿用 `/api/v1/` 响应结构、服务端
会话取班级、`X-Request-ID` 日志关联和 `make check` 门禁，不修改这些既有契约。
